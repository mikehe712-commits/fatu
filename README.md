# 写了就发 · 复刻版

Markdown 自动排版为小红书图文卡片或公众号长文。零依赖、纯静态、本地可跑。

复刻自 [fawen.fun](https://fawen.fun) / [fxyadela/write-then-publish](https://github.com/fxyadela/write-then-publish)（MIT）。
本目录是独立重写，不含原项目的后端配置或云端凭据。

```bash
python3 "写了就发-复刻/server.py" 4173
```

然后打开 <http://127.0.0.1:4173>。直接双击 `index.html` 也能用（没有构建步骤，没有 CDN 依赖）。

## 一、跟原版对齐的部分

输出规格与原版一致：**1728 × 2304 PNG**（864 × 1152 逻辑像素 @2×），正文默认 34 号、行距 1.85，
卡片内边距 42、头像区高 158、底部留白 62 — 这些几何量都照抄原版，所以同一份文案的分页落点基本一致。

| 能力 | 说明 |
| --- | --- |
| 自动分页 | 用 canvas 实测字宽换行，按卡片高度切页 |
| 标记语法 | `#`/`##`/`###`、`**粗**`、`*斜*`、`` `码` ``、`> 引用`、有序/无序列表、`---`、表格、`[[image:id]]` |
| 行内上色 | `{{color:#hex\|文字}}`、`{{bg:#hex\|文字}}` |

## 二、性能优化

原版每次按键都会把全文重排一遍，热路径上有四处开销。逐条说明和实测：

### 1. 字宽测量：平均快 6.5×

原版 `graphemeSegments()`（app.js:4374）**每个 token 都 `new Intl.Segmenter()`**，
`glyphWidth()`（app.js:4501）**每个字都重设 `ctx.font`**。两者都是很贵的操作：
`Intl.Segmenter` 要初始化 ICU，`ctx.font` 赋值要重新解析字体简写。

复刻版把 segmenter 提为单例、按原文串缓存断行单元、按 `font|text` 缓存字宽，
并且只在字体真的变化时才赋值 `ctx.font`。

打开 [`bench.html`](bench.html) 可自行复测（本机 Chrome 实测）：

| 文档规模 | 字符数 | 原版写法 | 复刻版 | 提速 |
| --- | --- | --- | --- | --- |
| 40 行 | 1,457 | 1.57 ms | 0.38 ms | **4.1×** |
| 120 行 | 4,457 | 3.57 ms | 0.44 ms | **8.1×** |
| 240 行 | 8,957 | 6.00 ms | 0.83 ms | **7.2×** |
| 480 行 | 18,089 | 10.90 ms | 1.67 ms | **6.5×** |

两种写法输出的宽度完全一致（bench 页里逐行断言），只是缓存策略不同。

### 2. 内存：从随篇幅线性增长变成恒定

一张卡片的画布是 1728 × 2304 × 4 字节 ≈ **16 MB**。原版把每一页都建成 canvas 挂在 DOM 上，
40 张卡片就是 ~640 MB。

复刻版只给视口附近（上下各 800px）的卡片建画布，滚出去就把 `canvas.width/height` 置 0 释放显存，
位置由骨架屏用 `aspect-ratio` 占住，所以滚动不跳。40 张卡片实测常驻 **2–4 张画布、约 30 MB**，
且不随篇幅增长。

### 3. 导出文字真正按 2× 绘制

原版 `renderPage()`（app.js:4714）先在 864 × 1152 画布上画完，再用
`imageSmoothingEnabled = false` 放大到 1728 × 2304，只有图片是补画的高清层 —
也就是说导出图里的**文字是像素放大的**。

复刻版直接 `ctx.setTransform(2, 0, 0, 2, 0, 0)` 在最终分辨率上绘制，文字是原生 2× 光栅化，
同时省掉了每页一次的整幅画布拷贝。

### 4. 分级失效：改颜色不再重新分页

颜色在原版是排版期烘进 style 的，所以拖一下取色器就要全文重排。
复刻版把颜色移到绘制期解析（`styleFor()` 不含颜色），于是：

- 改文字/强调/背景色、改昵称头像 → 只重绘可见画布
- 改字号/行距/字体/图片高度、改正文 → 才重新分页

两类失效在同一个 `requestAnimationFrame` 里合并，一次按键不会做多余的活。

### 5. 去掉全部第三方依赖

原版从 CDN 加载 supabase-js、html2canvas、lucide，另外自带 JSZip，合计约 400 KB 阻塞脚本。
复刻版：图标是内联 SVG，ZIP 用自写的 STORE 写入器（[`src/zip.js`](src/zip.js)，~90 行），
长图用同一套排版引擎跑「连续模式」而不是 html2canvas。

整体也小了一圈（原版 `app.js` 7,970 行 / 298 KB，`styles.css` 4,084 行 / 71.7 KB）：

| | 复刻版 | 原版 |
| --- | --- | --- |
| 逻辑 | 2,481 行 / 92 KB（engine + app + zip） | 8,220 行 / 393 KB（app + supabase + JSZip） |
| 样式 | 703 行 / 23 KB | 4,084 行 / 72 KB |
| CDN 依赖 | 无 | supabase-js、html2canvas、lucide |

功能少了一部分（见下节），行数差距不能全算优化；但同一份核心排版逻辑确实短得多。

## 三、交互改进

原版的自动分页有个根本问题：**写的时候看不见页会切在哪**。这一版补的主要是这类反馈。

- **编辑区行号栏显示分页落点** — 每页起始行画一条虚线和页码，当前页高亮。写的时候就知道会切在哪。
- **手动分页** — 一行 `===` 强制切页，`⌘⏎` 插入。原版只能靠调字号去凑。
- **光标 ⇄ 卡片双向联动** — 移动光标，右边高亮并滚到对应卡片；点卡片上的文字，光标跳回原文那一处。
- **剪贴板直接粘图** — `⌘V` 贴图即插入；编辑区和预览区都能拖入图片。原版必须走文件选择器。
- **超出画布会明说** — 单张图或单行放不进一页时，卡片下方标「内容超出」并在状态栏提示，而不是静默裁掉。
- **导出可取消、有真进度** — 逐页之间让出一帧，导出时界面不冻。
- **完整快捷键**（`⌘/` 查看）— 加粗/斜体/标题/引用/列表/分页/插图/查找/导出/新建/历史/深浅色。
- **预览密度可切** — 单列看细节、双列排版、三列看整体节奏。
- 面板可拖宽、`Tab` 在编辑区缩进而不是跳焦点、弹层互斥且点外关闭、`prefers-reduced-motion` 生效。

## 四、没有复刻的部分

这些依赖原项目的后端或系统能力，本目录明确不做（不是漏了）：

- **Supabase 账号登录与云同步** — 原项目的 `publishableKey` 写在前端源码里，复刻版不使用他人后端，改为纯本地 localStorage。
- **Obsidian 双向同步** — 需要 File System Access API 授权目录，且写回仓库有破坏性风险。
- **Live Photo / 实况图片** — 需要视频转码与平台发布包封装。
- **公众号草稿箱同步** — 需要微信 API 凭据。
- **图片裁剪器** — 保留了裁剪数据结构（`crop`）和引擎支持，但没做拖拽裁剪 UI；目前提供宽度百分比和左/中/右对齐。

## 五、文件结构

```
写了就发-复刻/
├── index.html          结构
├── bench.html          热路径对比，可自行复测
├── server.py           本地静态服务
└── src/
    ├── engine.js       Markdown → 区块 → 分页排版 → canvas 绘制（纯逻辑）
    ├── app.js          状态、虚拟化、交互
    ├── styles.css      设计系统（浅/深色）
    └── zip.js          STORE 模式 ZIP 写入器
```

`engine.js` 不碰 DOM（除了一个测量用画布），`layout()` 是同步纯函数 —
所以它既能给屏幕上的卡片排版，也能给长图跑连续模式，还能在 `bench.html` 里直接压测。

调试钩子：`window.__bench(20)` 测排版耗时，`window.__flush()` 强制跑完一帧（无头环境下 rAF 不触发时有用）。

## 六、已知限制

- **批量 ZIP 里的中文文件名**：按 ZIP 规范设了 UTF-8 标志位，macOS 访达（`ditto`）、Windows、Linux 现代工具都正常；
  但 macOS 自带的命令行 `unzip`（Info-ZIP 6.0）不认这个标志位，会显示成 `????`。用访达双击解压即可。
- 表格按等宽列排，不支持列宽自适应和对齐标记（`:---:`）。
- 长文的「复制公众号格式」依赖浏览器剪贴板 API，需在 HTTPS 或 localhost 下使用。
